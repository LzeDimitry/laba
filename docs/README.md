# Documentation — Secure Update Client

Точка входу в документацію проєкту. Структура відповідає політиці ведення
документації (`docs/policy/project_policy.md`).

## Структура

```
docs/
├── README.md                  # цей файл — точка входу
├── user/                      # документація для користувача
├── spec/                      # зовнішня специфікація (що робить продукт)
├── internal_spec/             # внутрішня специфікація (як влаштований)
│   ├── modules_registry.md    # реєстр модулів
│   └── modules/               # опис поведінки кожного модуля
├── development/               # інженерна документація
│   ├── build/                 # збірка та реліз
│   ├── tests/                 # стратегія тестування
│   └── architecture/          # архітектура та діаграми
├── design/                    # продуктовий і візуальний дизайн
│   ├── product/
│   └── gui/
├── policy/                    # політики проєкту
│   ├── project_policy.md
│   ├── security_policy.md
│   └── privacy_policy.md
├── security/                  # безпекова документація
│   ├── threat_model.md
│   └── security_requirements.md
└── templates/                 # шаблони документів
```

## Правила

1. Кожен документ має блок метаданих: назва, версія, статус, дата, власник.
2. Документ вважається чинним лише після коміту в `main`.
3. При зміні архітектури обов'язково переглядаються `security/threat_model.md`
   та `security/security_requirements.md`.
4. Мова документів — українська; назви файлів і тек — латиницею.
