## 1. Що потребує захисту

| Об'єкт | Цілісність | Автентичність | Механізм |
| --- | :---: | :---: | --- |
| Пакет оновлення | так | так | SHA-256 у манифесті + підпис манифесту |
| Манифест оновлення | так | так | підпис RSA-PSS / Ed25519 |
| Конфігурація клієнта | так | ні | SHA-256 + еталон у підписаному манифесті |
| Локальний кеш | так | ні | SHA-256 після завантаження |
| Журнали аудиту | так | так | HMAC-SHA256 |
| Записи телеметрії | так | так | HMAC-SHA256 |
| Ліцензія | так | так | RSA-PSS (ЛР8) |
| Внутрішні повідомлення сервісів | так | так | AES-GCM |

## 2. Вибір механізму

- **SHA-256** використовується там, де достатньо виявити випадкове
  пошкодження або розбіжність із еталоном, а еталон походить із довіреного
  джерела (манифест підписаний).
- **HMAC-SHA256** — там, де обидві сторони мають спільний секрет, а
  походження даних потрібно підтвердити без асиметричної криптографії
  (журнали, телеметрія).
- **AES-GCM** — там, де потрібні одночасно конфіденційність і цілісність
  (резервні копії, внутрішні повідомлення).
- **RSA-PSS** — там, де перевіряюча сторона не повинна мати секрету
  (підпис релізів та ліцензій).

Чистий хеш без ключа не використовується як єдиний захист від підміни: якщо
зловмисник контролює і дані, і еталон, він узгодить обидва.

## 3. Де зберігаються еталони та ключі

| Значення | Місце зберігання |
| --- | --- |
| SHA-256 пакетів | у підписаному манифесті (доставка разом з релізом) |
| Відкритий ключ підпису | вбудований у клієнт (pinned) |
| Ключ HMAC журналів | файл поза репозиторієм, права 0600 |
| Ключ AES-GCM | окреме сховище секретів |

## 4. Коли виконується перевірка

1. Після отримання манифесту — перевірка підпису до читання будь-яких полів.
2. Після завантаження пакета — обчислення SHA-256 і порівняння з манифестом.
3. Безпосередньо перед застосуванням — повторна перевірка хешу файлу зі
   staging-каталогу (захист від TOCTOU).
4. Під час запису журналу — HMAC обчислюється і зберігається разом із записом.
5. Під час читання журналу — HMAC перевіряється перед відображенням.

## 5. Реакція на невдалу перевірку

| Подія | Реакція |
| --- | --- |
| Невірний підпис манифесту | оновлення не застосовується, подія в журнал, користувачу — загальна помилка |
| Розбіжність SHA-256 пакета | пакет видаляється з кешу, повторна спроба не більше 3 разів |
| Невірний HMAC журналу | запис вважається пошкодженим, доступ до нього блокується |
| Помилка AES-GCM (InvalidTag) | дані не розшифровуються, ініціюється перевірка цілісності резервної копії |

Усі відмови є «fail closed»: сумнівні дані не використовуються.

## 6. Результати експериментів

- Зміна одного символу повідомлення змінює близько 131 біта з 256 у SHA-256.
- HMAC реагує на зміну одного біта ключа: різниця у 144 бітах із 256.
- AES-GCM виявляє підміну одного байта шифротексту (`InvalidTag`).

## 7. Простежуваність

| Вимога | Реалізація |
| --- | --- |
| SR-01, SR-05 | перевірка підпису та SHA-256 у клієнті |
| SR-06 | повторна перевірка хешу перед застосуванням |
| SR-26 | відмова від установки за будь-якої помилки перевірки |
